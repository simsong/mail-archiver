# Microsoft 365

## END USER

### Current status: no supported Microsoft 365 import

Email Collection Toolkit cannot currently ingest a live Microsoft 365 or Outlook.com
mailbox, PST, OST, or Outlook for Mac OLM archive. Do not interpret successful
provider detection by `mailarchiver-auth` as mailbox support; the command
currently reports `Microsoft Office not yet implemented.`

Microsoft does not provide a platform-neutral, provider-hosted equivalent of
Google Takeout for an individual Microsoft 365 mailbox. The closest end-user
export paths require a desktop version of Outlook:

- **Windows:** New Outlook and classic Outlook can export a mailbox to PST.
  Before export, the user must configure Outlook to download **All** mail;
  Microsoft warns that Cached Exchange Mode exports only the locally cached
  items.
- **macOS:** Legacy Outlook for Mac can export OLM. Microsoft says this feature
  is available only in Legacy Outlook for Mac.
- **Outlook.com:** Microsoft directs users to desktop Outlook and the same PST
  or legacy-Mac OLM workflows.

These files are useful future acquisition sources, but none is accepted by the
current Email Collection Toolkit release. Consequently there is presently no supported
complete M365 export workflow analogous to Gmail Takeout.

### Interim recovery through Apple Mail

If the Microsoft 365, Exchange Online, or Outlook.com account is already
synchronized with Apple Mail, Email Collection Toolkit can ingest the complete `.emlx`
records below `~/Library/Mail`. This is an implemented local-file path and does
not require Email Collection Toolkit to register an Entra application. It is best-effort
recovery rather than a complete provider export: Apple Mail may retain partial
records or detached content.

The ingest can be rerun as Apple Mail downloads more content. Byte-identical
copies from a backup and the cache share one canonical message while retaining
both source observations. Apple-rewritten raw variants are preserved
separately and related by the archive's `h3` semantic-message hash. See
[APPLE_MAIL_CACHE.md](APPLE_MAIL_CACHE.md).

References:

- [Export Outlook data to PST](https://support.microsoft.com/en-us/outlook/export-emails-contacts-and-calendar-items-to-outlook-using-a-pst-file)
- [Export an Outlook.com mailbox](https://support.microsoft.com/en-us/outlook/export-your-outlook-com-mailbox)
- [Export OLM from legacy Outlook for Mac](https://support.microsoft.com/en-au/office/export-items-to-an-archive-file-in-outlook-for-mac-281a62bf-cc42-46b1-9ad5-6bda80ca3106)

## DEVELOPER

### First planned live acquisition: IMAP

Generic read-only IMAP is the first planned cloud importer because its
acquisition, checkpoint, and exact-byte pipeline can also serve Gmail and
conventional IMAP providers. Exchange Online authentication uses the bundled
multitenant public desktop client and delegated `IMAP.AccessAsUser.All`; it
does not use Basic Authentication. The per-archive source records server,
port, username, folder selection, authentication mode, and only a non-secret
credential reference. OAuth tokens remain in the operating-system keychain.

### Later provider-specific acquisition: Microsoft Graph

A later live adapter should use Microsoft Graph with delegated `Mail.Read` and
retrieve MIME content through the message `/$value` endpoint. Delegated access
limits the application to the signed-in user's mailbox; application-wide
permissions are unnecessary and must not be requested.

The distributor registers one Microsoft Entra application and configures it as
a multitenant public desktop client. To cover both organizational M365 accounts
and Outlook.com, its sign-in audience is **Accounts in any organizational
directory and personal Microsoft accounts**. The public client ID is bundled
with Email Collection Toolkit. A desktop public client cannot safely hold a client secret,
so no secret is created or distributed.

Microsoft marks delegated `Mail.Read` as not requiring administrator consent by
default and supports it for organizational and personal Microsoft accounts.
Individual tenants can nevertheless disable user consent or require an
administrator to approve Email Collection Toolkit.

References:

- [Microsoft account audiences](https://learn.microsoft.com/en-us/entra/identity-platform/single-and-multi-tenant-apps)
- [Public desktop clients](https://learn.microsoft.com/en-us/entra/identity-platform/msal-client-applications)

### Publisher verification and assessment

Microsoft does not impose Google's restricted-scope/CASA annual assessment on
this desktop Graph integration. Publisher Verification is a separate,
no-charge organizational identity check. It adds a verified-publisher badge and
is operationally important because many M365 tenants allow user consent only
for verified publishers or locally registered applications. It requires an
organizational Entra tenant, a verified domain, and a verified Microsoft AI
Cloud Partner Program account. Publisher Verification is not an application
security audit and does not certify software quality.

There is no Microsoft test-user list, seven-day testing authorization, or
Google-style lifetime 100-user cap. Token renewal and reauthentication instead
follow Microsoft identity, tenant consent, Conditional Access, and revocation
policies.

References:

- [Microsoft Publisher Verification](https://learn.microsoft.com/en-us/entra/identity-platform/publisher-verification-overview)
- [User and administrator consent](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/user-admin-consent-overview)

### IMAP is not an authentication shortcut

Exchange Online has removed Basic Authentication for IMAP. OAuth IMAP still
requires the same one-time Entra application registration and the delegated
`IMAP.AccessAsUser.All` permission. That permission grants read/write IMAP
access as the signed-in user, while Graph `Mail.Read` is narrower and accurately
describes Email Collection Toolkit's behavior. Tenant consent restrictions still apply.
IMAP is therefore the shared first transport, not a way to avoid registration.

References:

- [Exchange Online IMAP OAuth](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth)
- [Exchange Online Basic Authentication retirement](https://learn.microsoft.com/en-us/lifecycle/announcements/basic-auth-deprecation-exchange-online)
- [`IMAP.AccessAsUser.All`](https://learn.microsoft.com/en-us/graph/permissions-reference#imapaccessasuserall)

### Offline formats

PST and OST support is planned behind a typed source-adapter boundary using
libpff/pypff, with explicit reporting whenever a provider object must be
reconstructed rather than preserved as original RFC 5322 bytes. OLM is a
different format and needs a separate implementation and fixture corpus. An
Outlook export must never be described as complete without recording the
client, version, synchronization range, folders selected, and item counts.

Live OAuth IMAP, Microsoft Graph, PST/OST, and OLM acquisition all remain
unimplemented.

Apple Mail cache acquisition is distinct from those provider adapters. It
uses the existing local EMLX reader, records a cache relationship when it can,
and cannot assert server completeness.
